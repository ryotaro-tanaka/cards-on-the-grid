# カード実装タスク分解

## 前提
- 目的: `docs/game_rules.md` にあるカード（Move / Assault / Arrowrain / Rock Bombardment / Lightning / Recharge / Doping / Barrier / Breath / Mine / Stealing）を、`core` / `backend` / `frontend` へ段階的に実装する。
- 方針: ルールの真実源は `core` とし、`backend` は順序・認可・配信、`frontend` は入力と表示に専念する。
- 依存: 仕様の未確定点（例: 手札上限超過時処理、補充配置の任意選択、Move と Assault の住み分け）は先に決める。

---

## フェーズ0: 仕様確定（実装前に必須）

### 0-1. 未確定仕様の決定
- [x] 手札上限（5枚）を超えるドロー時は、ランダムに手札を1枚捨ててからドローする。
- [x] Mine の設置先は死守陣地を除く自分の陣地のみ（You: A2〜G2, A3〜G3 / Opponent: A5〜G5, A6〜G6）。
- [x] Recharge は使用済みのアクティブスキル（Ninja / Bomber / Giant Boa / Alchemist）のみ対象。未使用スキルには使用不可。
- [x] 山札の疑似乱数仕様: 試合開始時に 64bit シードを決定し、各ドローで同一重みテーブルから抽選。イベント順が同一なら再現可能。
- [x] Move と Assault の役割: どちらもカード起因の1マス移動。Move は攻撃なし、Assault は攻撃あり。通常移動権とは別管理。
- [x] Stealing の対象選定: 相手手札から一様ランダムで1枚選ぶ。相手が空手札の場合は使用不可。

### 0-2. 実装仕様書の更新
- [x] `docs/game_rules.md` に未確定項目の決定内容を追記。
- [x] `docs/api.md` にカード使用 Intent とサーバーイベントの JSON 例を追加。
- [x] `docs/progress_report.md` のロードマップに「カード実装フェーズ」を追加。

## フェーズ2: core のカード効果実装（カード別）

### 2-1. 移動系
- [x] Move: 「1マス移動（攻撃なし）」を実装（既存自動戦闘の抑止制御を追加）。
- [x] Assault: 「1マス移動＋攻撃あり」を実装。

### 2-2. ダメージ系
- [x] Arrowrain: 敵1体に1ダメージ。
- [x] Rock Bombardment: 自陣地内の敵1体に2ダメージ。
- [x] Lightning: 敵陣地内のモンスター1体に3ダメージ。
- [x] ダメージで死亡した場合の後続処理（盤面除去、補充キュー）を統一。

### 2-3. 補助・強化系
- [x] Recharge: 対象モンスターのアクティブスキル使用済み状態をリセット。
- [x] Doping: 対象へ `+0/+1`（現在HP/最大HPの扱いを仕様通りに実装）。
- [x] Barrier: 対象へ `+1/+0`。
- [x] Breath: 対象へ `+1/+1`。

### 2-4. トリッキー系
- [x] Mine: 地雷設置と盤面管理を実装。
- [x] 地雷踏破時のダメージ・除去処理（必要ならイベント化）を実装。
- [x] Stealing: 相手手札からランダム1枚奪取を実装。

### 2-5. イベント適用
- [x] `applyCommand` でカード関連イベントを生成。
- [x] `applyEvent` にカード関連イベントの反映処理を追加。
